Before Step 1

Morgan: “Where are we running?”

1 Prove who / where you are

What this does: Reads session identity and account location — Cloud Services metadata, not a warehouse scan of table bytes.

Why: Exam questions mix “account locator,” region, and warehouse. Separate them.

SQL · account context
USE ROLE ROLE_CORE_LAB_ADMIN;
USE WAREHOUSE WH_CORE_XS;
USE DATABASE ALPINE_RETAIL;
USE SCHEMA LAB;

SELECT CURRENT_ACCOUNT() AS account_locator,
       CURRENT_REGION()  AS region,
       CURRENT_ROLE()    AS role,
       CURRENT_WAREHOUSE() AS warehouse;
✓ You should see a locator, a region string, ROLE_CORE_LAB_ADMIN, WH_CORE_XS

Before Step 2

Kai: “What are PARAMETERS?”

2 Peek at retention parameters

What this does: Shows account-level knobs tied to Time Travel retention.

What you should see: A value (often 1 on trials). Remember: Enterprise unlocks up to 90 days — your trial number ≠ the exam rule.

SQL · SHOW PARAMETERS
SHOW PARAMETERS LIKE 'DATA_RETENTION_TIME_IN_DAYS'
  IN ACCOUNT;

SHOW PARAMETERS LIKE 'MIN_DATA_RETENTION_TIME_IN_DAYS'
  IN ACCOUNT;
✓ Parameter rows appear — note the numeric value, don’t overfit trial quirks

Before Step 3

Sam: “Fail-safe is not free.”

3 Permanent vs transient tiny demo

What this does: Creates one permanent and one transient table so you can say “Fail-safe: yes vs no.”

SQL · permanent vs transient
CREATE OR REPLACE TABLE LAB.DEMO_PERM_TINY (
  ID NUMBER, NOTE STRING
);
CREATE OR REPLACE TRANSIENT TABLE LAB.DEMO_TRANS_TINY (
  ID NUMBER, NOTE STRING
);
INSERT INTO LAB.DEMO_PERM_TINY VALUES (1, 'has Fail-safe after TT');
INSERT INTO LAB.DEMO_TRANS_TINY VALUES (1, 'no Fail-safe');
SHOW TABLES LIKE 'DEMO_%' IN SCHEMA LAB;
✓ Two tables listed — note TRANSIENT kind on one of them

Exam presses further — say these out loud

Cover each answer before you open it. Domain 1 traps.

Q1. Does a virtual warehouse store table data?

Say: No. Warehouses are Query Processing (compute). Table data lives in Database Storage as compressed micro-partitions. Bigger warehouse ≠ more storage.

Q2. Which edition do you need for up to 90-day Time Travel?

Say: Enterprise or higher. Standard is capped at 1 day. Don’t confuse “my trial shows X” with the edition matrix.

Q3. How is Cloud Services billed?

Say: Cloud Services usage is metered; Snowflake applies a daily credit against warehouse compute. Heavy metadata / services beyond that can show as Cloud Services charges — it is not “free forever,” and it is not the same as warehouse credits.

Q4. What’s the benefit of separating storage and compute?

Say: Scale and pay for each independently: keep large history in storage while using a small warehouse for light queries, or spin up larger compute for spikes without moving data.

Q5. Tri-Secret Secure and AWS PrivateLink — which edition tier?

Say: Business Critical (and VPS). Enterprise adds Multi-cluster warehouses and longer Time Travel, but those hardened networking / key features are Business Critical+.

Q6. Name the three architecture layers in exam order.

Say: Database Storage, Query Processing (virtual warehouses), and Cloud Services (auth, metadata, optimizer).

Priya’s wrap-up (say this out loud)
“Alpine’s Snowflake is three layers: storage holds our micro-partitions, warehouses like WH_CORE_XS are compute only, and Cloud Services handles login, metadata, and planning. Editions matter — 90-day Time Travel needs Enterprise+; Tri-Secret and PrivateLink need Business Critical+. Transient tables skip Fail-safe. I will never say the warehouse stores data.”
