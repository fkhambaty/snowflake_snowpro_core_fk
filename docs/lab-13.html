1 Selective query (pruning-friendly shape)

What this does: Narrow filter. On a big table this is where pruning shines; our sample is tiny — still practice the Profile habit.

SQL · selective
USE ROLE ROLE_CORE_LAB_ADMIN;
USE WAREHOUSE WH_CORE_XS;
USE DATABASE ALPINE_RETAIL;
USE SCHEMA LAB;

SELECT ORDER_ID, CUSTOMER_ID, AMOUNT_USD, STATUS
FROM LAB.ORDERS
WHERE STATUS = 'PENDING';
✓ Open Profile — note TableScan / partitions (even if small)

2 Broader query + result cache demo

What this does: Run an aggregate, then the same SELECT twice to feel result cache. RESULT_SCAN re-reads the last result without re-running the original SQL.

SQL · aggregate
SELECT STATUS, COUNT(*) AS N, SUM(AMOUNT_USD) AS TOTAL_USD
FROM LAB.ORDERS
GROUP BY STATUS
ORDER BY TOTAL_USD DESC;
SQL · result cache + RESULT_SCAN
SELECT ORDER_ID, AMOUNT_USD
FROM LAB.ORDERS
WHERE CUSTOMER_ID = 1
ORDER BY ORDER_ID;

-- Run the identical statement again, then:
SELECT * FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));
✓ You can explain result cache vs RESULT_SCAN

Exam presses further — say these out loud

Q1. What is RESULT_SCAN for?

Say: Query a previous result set by query ID without re-executing the original SQL — handy for post-processing the last statement’s output.

Q2. When will a bigger warehouse NOT help?

Say: When the bottleneck is poor pruning (scanning almost everything), waiting on cloud services only, tiny data already memory-resident, or a bad SQL shape (exploding joins). Profile first.

Q3. What does spill mean in Profile?

Say: Operators ran out of memory and wrote intermediate data to local or remote storage. Remote spill is expensive latency-wise — scale up or reduce memory pressure.

Q4. When consider Query Acceleration Service?

Say: Large scans/filters that can offload to QAS serverless acceleration — especially ad-hoc analytical queries. Not a substitute for fixing cardinality explosions.

Q5. Name the three caches and who “owns” them.

Say: Result cache (cloud services — reused results), local disk cache (warehouse SSDs — warm data), metadata cache (cloud services — partition stats for pruning/planning).
