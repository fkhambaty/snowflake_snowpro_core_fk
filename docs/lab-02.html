Before Step 2

Riley: “Table first, then view.”

2 Table + view

What this does: Creates PRODUCTS and a cheap-SKU view.

SQL · table + view
USE SCHEMA LAB;

CREATE OR REPLACE TABLE LAB.PRODUCTS (
  PRODUCT_ID NUMBER, SKU STRING,
  NAME STRING, UNIT_PRICE NUMBER(10,2)
);
INSERT INTO LAB.PRODUCTS VALUES
  (1, 'ALP-TEE', 'Alpine Tee', 29.00),
  (2, 'ALP-HAT', 'Trail Hat', 19.50);
SQL · view
CREATE OR REPLACE VIEW LAB.V_PRODUCTS_CHEAP AS
SELECT PRODUCT_ID, SKU, NAME, UNIT_PRICE
FROM LAB.PRODUCTS
WHERE UNIT_PRICE < 25;

SELECT * FROM LAB.V_PRODUCTS_CHEAP;
✓ View returns Trail Hat only (19.50)

3 Sequence

What this does: Creates SEQ_ORDER_ID starting at 1000 and pulls two values.

SQL · sequence
CREATE OR REPLACE SEQUENCE LAB.SEQ_ORDER_ID
  START = 1000 INCREMENT = 1;

SELECT LAB.SEQ_ORDER_ID.NEXTVAL AS next_id;
SELECT LAB.SEQ_ORDER_ID.NEXTVAL AS next_id;
✓ First call ≈ 1000, second ≈ 1001

Before Step 4

Named stage vs user stage

4 File format + internal named stage

What this does: Creates a CSV recipe and an internal stage that references it.

SQL · format + stage
CREATE OR REPLACE FILE FORMAT LAB.FF_CSV_STD
  TYPE = CSV FIELD_DELIMITER = ','
  SKIP_HEADER = 1
  FIELD_OPTIONALLY_ENCLOSED_BY = '"';

CREATE OR REPLACE STAGE LAB.STG_INBOUND
  FILE_FORMAT = LAB.FF_CSV_STD;

SHOW STAGES IN SCHEMA LAB;
SHOW FILE FORMATS IN SCHEMA LAB;
✓ STG_INBOUND and FF_CSV_STD listed under LAB

Exam presses further — say these out loud

Cover each answer before you open it.

Q1. View vs materialized view — what’s the difference?

Say: A view is a saved query with no stored result set. A materialized view stores precomputed results and has refresh/cost implications. Don’t call every view an MV.

Q2. Named stage vs user stage?

Say: User stage (@~) is private to the user. A named stage is a schema object you can grant to roles — preferred for shared pipelines.

Q3. What objects are typically account-level?

Say: Warehouses, users, roles, and (among others) shares and account-level integrations. Tables/views/stages usually live in a schema inside a database.

Q4. Why attach a FILE FORMAT to a stage?

Say: So COPY / LIST consumers inherit the CSV/JSON parsing recipe. You can still override per statement — defaults reduce mistakes.

Q5. Pipe vs Task vs Stream — one sentence each?

Say: Pipe = continuous/auto load from stage. Stream = change-data feed on a table. Task = scheduled SQL (often after streams). Different jobs, different CREATE statements.

Priya’s wrap-up (say this out loud)
“In ALPINE_RETAIL.LAB I created PRODUCTS, view V_PRODUCTS_CHEAP, sequence SEQ_ORDER_ID, file format FF_CSV_STD, and named stage STG_INBOUND. Views don’t store results; MVs do. Named stages are shareable; user stages are personal. Warehouses and roles live at account level.”
